# 智慧校園生活

## 專案簡介
本專題以「智慧校園生活」為核心，目標是利用物聯網（IoT）、LoRaWAN、Node-RED、MySQL、LINE Bot 與網頁介面，建立一套可即時監測與查詢校園生活資訊的系統。

在一般校園生活中，許多資訊往往必須親自到現場才能確認，例如：

- 籃球場是否有人使用
- 停車場是否還有空位
- 餐廳便當剩餘數量
- 宿舍洗衣機是否正在使用
- 教室空氣品質與溫溼度狀況

這些資訊若無法即時取得，容易造成時間浪費與使用上的不便。因此，本系統透過感測器蒐集現場資料，並將資訊整合到 LINE 與網頁 UI，讓使用者能直接透過手機快速查詢校園生活相關狀態，提升便利性與效率。

## 研究背景與動機
隨著科技快速發展，智慧校園已逐漸成為教育場域的重要方向。從智慧教室、設備借用、學生證整合，到校園數位管理，智慧化技術正逐步改變學生、教職員與管理者的校園體驗。

然而，現有智慧校園系統多偏向行政管理或教學設備應用，對於學生「日常生活層面」的即時需求仍有改善空間。因此，本專題將焦點放在校園成員每天最常碰到的生活情境，希望打造一套更貼近真實需求、具擴充性且操作方便的智慧校園生活系統。

---

## 研究目的
本專題主要目的是：

1. 透過學生最常使用的通訊工具 **LINE** 作為主要互動介面，使校園資訊查詢更加直覺與方便。
2. 利用 **LoRaWAN** 的長距離、低功耗特性，解決大型校園中多點感測裝置的通訊問題。
3. 建立可擴充的智慧校園系統，逐步納入更多生活場景需求。
4. 讓使用者可以透過 **LINE Bot** 與 **網頁 UI** 即時查詢校園空間與設備狀態。
5. 提升校園生活品質，減少學生與教職員在資訊確認上花費的時間與成本。

---

## 研究範圍
本專題的研究範圍包含：

- 各類感測器的應用與整合
- LoRa / LoRaWAN 通訊方式
- Node-RED 後端流程設計
- MySQL 資料儲存與管理
- LINE Bot 使用者互動設計
- 網頁查詢介面開發

系統主要應用情境包括：

- 教室 CO2、溫度、濕度監測
- 停車場車位狀態監測
- 籃球場使用情況監測
- 食堂便當剩餘數量監測
- 宿舍洗衣機使用狀況監測

---

## 系統功能總覽
本系統共實作五大功能：

### 1. 教室環境監測
使用 **CO2 感測器** 與 **溫溼度感測器** 監控教室環境數據，提供：

- CO2 濃度
- 溫度
- 濕度

使用者可透過 LINE 或網頁指定查詢特定教室，並透過網頁 UI 的紅、黃、綠顏色顯示目前是否超出正常範圍。

### 2. 籃球場使用監測
透過 **振動感測器** 安裝於籃板或相關設備位置，偵測球場是否正在使用。  
使用者可透過 LINE 或網頁查詢目前哪些球場有人使用，藉此改去其他空閒球場。

### 3. 停車場車位監測
利用 **超音波感測器** 量測停車位上方至車輛的距離，以判斷車位是否有車輛停放，並統計剩餘空位數量。  
資訊可透過 LINE 與網頁 UI 查詢。

### 4. 餐廳便當數量監測
利用 **重量感測器** 與 **HX711 秤重模組**，透過重量變化估算特定種類便當的剩餘數量，並以 LINE 呈現查詢結果。

### 5. 洗衣機使用監測
利用 **電流感測器** 檢測洗衣機啟動前後的電流差異，藉此判斷洗衣機是否正在使用。  
使用者可透過 LINE 或網頁 UI 查詢宿舍洗衣機使用情況。

---

## 系統架構
本系統整體流程如下：

1. 各感測器定時蒐集現場資料
2. 感測器資料傳送至 **ESP32 / Wireless Stick Lite (V3)**
3. 透過 **LoRaWAN** 將資料封包化並傳送
4. 後端由 **Node-RED** 接收與處理資料
5. 資料寫入 **MySQL 資料庫**
6. 將結果串接至：
   - **LINE Bot**
   - **Web UI**
7. 使用者透過手機或網頁查詢即時資訊

## 開發工具與技術

### 軟體工具
- **Arduino IDE**  
  用於撰寫感測器控制程式，主要使用 C++ 開發。

- **Node-RED**  
  以 Node.js 為基礎的圖形化流程開發工具，負責後端流程控制、資料處理、資料庫串接與 LINE Bot 邏輯設計。

- **MySQL**  
  用於儲存感測器資料與系統運作紀錄。

- **LINE Bot Development**  
  透過 Webhook 建立使用者與伺服器之間的互動機制，使查詢結果能直接顯示於 LINE 中。

### 硬體設備
- **MHZ-14A**：CO2 感測器
- **DHT11**：溫溼度感測器
- **HC-SR04**：超音波距離感測器
- **SW420**：振動感測器
- **SCT-013**：非侵入式電流互感器
- **HX711**：秤重放大器
- **Wireless Stick Lite (V3)**：IoT 節點開發板（ESP32-S3 + SX1262 LoRa）

## LoRaWAN 技術說明
本專題選擇 LoRaWAN 作為主要通訊方式，原因在於其具備以下優勢：

- **長距離傳輸**
- **低功耗**
- **較佳穿透性**
- **適合大型校園多點佈署**
- **可降低布線成本**

台灣現行可用頻段為 **920 MHz ~ 925 MHz**。

### 啟用方式
LoRaWAN 常見啟用方式包括：

#### OTAA（Over-The-Air Activation）
透過動態加入網路取得金鑰。

**優點**
- 安全性較高
- 擴充性較佳
- 適合新設備加入

**缺點**
- 設定較複雜
- 啟用時間較長

#### ABP（Activation By Personalization）
設備預先設定 DevAddr、NwkSKey、AppSKey，直接進行通訊。

**優點**
- 設定較簡單
- 啟動快速
- 功耗可能較低

**缺點**
- 安全性較 OTAA 低
- 靜態金鑰若外洩，風險較高

### LoRa 裝置類型
LoRa 裝置主要有三種類型：

- **Class A**：最省電，最常見
- **Class B**：功耗與即時性介於 A 和 C 之間
- **Class C**：接收視窗幾乎持續開啟，延遲低但功耗高

## 研究方法
本專題主要透過以下方式進行系統開發與驗證：

### 1. 軟硬體程式設計與改寫
參考現有函式庫範例，進行感測器程式、LoRaWAN 傳輸與資料整合的實驗與修改。

### 2. 技術討論與設計調整
透過與指導教授討論，釐清 LoRaWAN 設定、感測器整合、系統架構與應用情境。

### 3. 網路資料蒐集
參考感測器規格、接腳圖、函式庫與原始碼範例，完成硬體接線與程式撰寫。

### 4. 效能與可行性評估
系統評估包含：

- **LoRaWAN 傳輸效能測試**  
  測試校園不同區域中的傳輸距離、穩定性、傳輸速率與封包丟失率。

- **Node-RED 資料處理與儲存效能測試**  
  驗證即時處理大量感測資料的能力。

- **LINE Bot 與網頁介面使用者評估**  
  檢查操作是否直觀、功能是否足夠、資訊呈現是否清楚。

- **整體系統整合測試**  
  模擬實際使用情境，驗證感測器、LoRaWAN、Node-RED、資料庫、LINE Bot 與網頁之間是否能穩定協同運作。

## 研究成果
本專題完成了智慧校園生活系統的基本架構與五大生活應用模組，並透過 Node-RED 完成：

- 感測器資料接收
- 後端資料處理
- 資料儲存
- LINE Bot 查詢流程
- Web UI 顯示流程

研究成果顯示，本系統具備以下價值：

1. 能即時提供校園生活資訊
2. 可減少使用者現場確認的時間成本
3. 架構具擴充性，未來可新增更多感測應用
4. 適合應用於大型校園環境
5. 能將校園數位化更貼近日常生活場景

## 結論
智慧校園的核心不只是提升校園管理效率，更應貼近校園成員的真實生活需求。本專題以「智慧校園生活」為主題，將焦點放在學生與教職員每天會碰到的生活情境，透過感測器、LoRaWAN、Node-RED、LINE Bot 與網頁介面，建立一套即時、便利、可擴充的智慧校園系統。

本系統證明了以 IoT 技術整合校園生活資訊的可行性，也顯示未來若結合 AI 與更完整的資料分析技術，智慧校園將可進一步提升到更高層次，成為更人性化、更有效率的數位校園環境。
